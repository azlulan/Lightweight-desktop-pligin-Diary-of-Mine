# Diary of Mine · 个人日记本

Diary of Mine 是一款 Windows 本地日程、日记与工作计时工具。当前桌面端已经包含月历日程、单日分钟级时间轴、批量 Task、便签与灵感、图文日记、工作模式、提醒、悬浮窗、设置及 Windows 本机注册；应用为单进程 WPF 程序，不依赖 HTTP 后端。

> 当前状态：v1.1.1 发布物已生成，仍待项目所有者完成最终运行验收。仓库目前以源码和开发资料为主；正式公开发布前还需确定开源许可证并确认图片、图标及公开联系方式的授权范围。

## 当前功能

- 日程表：固定六周月历，支持 `Class`、`Key`、`Idea`、`Task`，可创建、编辑、标记完成、拖拽边界、甩飞删除并分别撤销/重做。
- 单日详情：一条逻辑 24 小时时间轴，随窗口宽度自动一行或折为两行；支持缩放、平移、分钟级编辑、重叠项目轮换、当天时间线、Idea、灵感及日记入口。
- Task：按日期范围与多个星期规则批量生成 Key；月历中单列展示。删除或拖动某次 occurrence 只影响当天，双击编辑则修改整个批次。
- 日记：按日期排列与关键词/数字搜索，正文支持富文本式换行、复制粘贴与块级图片；手动保存、退出及 Esc 均会尝试保存。
- 工作模式：目标管理、分钟级录制、跨午夜（最长 24 小时）、中断覆盖、日期切换、今日/累计统计与名称/时长排序。
- Windows 交互：托盘、悬浮窗快捷面板、全局展开热键、开机自启、应用注册、提醒窗口及单实例运行。

## 技术与分层

| 层次 | 项目 | 职责 |
| --- | --- | --- |
| 领域 | `DiaryOfMine.Domain` | 日程、Task、日记、工作模式的数据模型与不变量 |
| 应用 | `DiaryOfMine.Application` | 用例服务、仓储接口、提醒规划、色板槽位解析 |
| 基础设施 | `DiaryOfMine.Infrastructure` | JSON 存储、旧数据迁移、设置、日志和本地路径 |
| 桌面端 | `DiaryOfMine.Desktop` | WPF 窗口、ViewModel、绘制与拖拽、托盘和 Windows 集成 |

目标框架为 .NET 9；桌面端为 `net9.0-windows`，启用 WPF、Windows Forms 与 Per-Monitor V2 DPI。项目当前没有第三方 NuGet 依赖。

```text
DiaryOfMine.sln
src/
  DiaryOfMine.Domain/
  DiaryOfMine.Application/
  DiaryOfMine.Infrastructure/
  DiaryOfMine.Desktop/
packaging/                    自定义安装器、卸载器源码
tools/package_demo.ps1       Demo 发布与 IExpress 打包脚本
docs/
  ai/                         面向后续 AI/开发工作流的当前源码索引
  architecture.md
  development.md
  logging.md
```

依赖方向为：`Desktop -> Application + Infrastructure`、`Infrastructure -> Application`、`Application -> Domain`。大量日程画布和拖拽交互位于 WPF code-behind；持久化变更仍通过 ViewModel/Application Service 进入仓储，不应在界面代码中直接改 JSON。

## 启动与调试

使用 Visual Studio 2022 的“.NET 桌面开发”工作负载，打开 `DiaryOfMine.sln`，将 `DiaryOfMine.Desktop` 设为启动项目。也可以在仓库根目录执行：

```powershell
dotnet run --project .\src\DiaryOfMine.Desktop\DiaryOfMine.Desktop.csproj
```

Debug 与 Release 使用不同的应用数据根目录：

- Debug：`%LOCALAPPDATA%\DiaryOfMine.Dev\userdata`
- Release：`%LOCALAPPDATA%\DiaryOfMine\userdata`

当前主要业务数据保存在设置指定的缓存目录：

- `DiaryOfMine.userdata.json`：日程、Idea、灵感及 Task occurrences
- `DiaryOfMine.diary.json`：日记标题、检索文本和 Base64 文档包（包括插入图片）
- `DiaryOfMine.work.json`：工作目标、录制区间和中断区间

上述当前格式是可移植的明文 JSON，不应描述为加密存储。程序仅保留从旧版 DPAPI `userdata\vault\calendar.dat` 向现行日程 JSON 的一次性迁移能力。发布和分享时严禁携带任何用户缓存、日志或测试录入内容。

## 获取与安装

- 当前仓库提供源码构建方式；公开发布后，面向普通用户的安装包应仅通过 GitHub Releases 等明确的官方渠道提供。
- 运行平台为 Windows x64。源码构建需要 .NET 9 SDK；使用 Visual Studio 时需安装“.NET 桌面开发”工作负载。
- `artifacts/`、`bin/`、`obj/`、`.vs/` 和用户数据均被排除在版本控制之外，不应随源码提交。
- 安装、升级和卸载前建议备份 `%LOCALAPPDATA%\DiaryOfMine\userdata`，尤其是在跨版本迁移前。

## 隐私与安全

Diary of Mine 默认离线运行，不包含遥测、云同步或 HTTP 后端。当前业务数据为明文 JSON；这意味着具有相应 Windows 文件访问权限的程序或账户可能读取内容。请勿将真实日记、缓存、日志、转储或测试数据提交到仓库或公开 Issue。

安全问题请按照 [安全策略](SECURITY.md) 私下报告。普通缺陷与功能建议可使用 GitHub Issue 模板。

## 更新与修改标准

以下规则是上一阶段开发形成的统一变更标准，后续修改均应遵循：

1. 先确认领域数据规范与跨层联动，再修改界面；界面不得绕过 Service/Repository 直接写业务文件。
2. 保留请求范围外的现有功能、快捷键、数据和窗口行为。需要改变既有约定时，应明确记录迁移或兼容策略。
3. 新增或修改功能时，同步更新 `docs/ai/` 中受影响的模块说明、修改入口、风险点和“最后核对日期”。
4. Class、Key 与工作模式颜色使用稳定的逻辑槽位键；设置色板改变后，既有项目也应动态使用新颜色，不能把当时的十六进制颜色固化为业务含义。
5. 桌面 UI 延续现有系统感、柔和浅色和圆角控件；新增有边框按钮应采用统一圆角样式，避免单独形成割裂的视觉体系。
6. 月历与单日详情拥有独立的撤销/重做历史；Task 的“单次 occurrence 编辑”和“整个批次编辑”必须保持不同语义。
7. Debug/Release 数据必须隔离；任何 Demo、安装包、完整软件目录都不得包含私人数据、缓存、日志或开发测试输入。
8. 源码修改与发布物生成分开处理。除非任务明确要求，不重新生成安装包；更新日志必须说明是“源码完成”“已打包”还是“已验收”。
9. 验证应与风险相称：默认完成必要的静态检查或编译检查，不做过度模拟运行；最终运行验收由项目所有者执行。
10. 安装器需保留自定义安装位置、程序与卸载器、开始菜单/App Paths 注册、桌面和任务栏选项、可控的完成后启动，并清理临时解包目录；卸载默认保留用户数据。
