# 开源发布检查清单

## 发布前阻断项

- [ ] 项目所有者选择许可证并提交根目录 `LICENSE`。
- [ ] 确认 `DiaryOfMine.png`、`DiaryOfMine.jpg`、`DiaryOfMine.ico` 的原创性或再分发授权。
- [ ] 确认应用内开发者邮箱是否愿意长期公开；如不愿意，改为专用支持地址。
- [ ] 项目所有者完成 v1.1.1 的最终运行验收。
- [ ] 决定 GitHub 仓库名称、简介、可见性和默认分支。

## 首次推送前

- [x] README 包含功能、构建、数据、隐私和贡献入口。
- [x] 补充贡献指南、安全策略、行为准则和更新日志。
- [x] 补充 Issue/PR 模板及最小编译 CI。
- [x] 忽略 `artifacts/`、`bin/`、`obj/`、`.vs/`、日志、缓存、数据库和密钥类文件。
- [ ] 使用 `git status --ignored` 检查首次暂存范围。
- [ ] 确认提交中不存在真实日记、缓存、日志、转储和本机绝对路径。

## GitHub 仓库创建后

- [ ] 添加仓库简介、主题标签和 Windows 平台说明。
- [ ] 启用 Private vulnerability reporting。
- [ ] 根据维护方式设置默认分支保护和 Pull Request 要求。
- [ ] 等首次 CI 通过后再创建版本标签。
- [ ] 用所有者验收过的产物创建 GitHub Release，并附 SHA-256 校验值。
- [ ] 在 README 中加入实际仓库、Release 和截图链接。

## 后续维护

- [ ] 在 .NET 9 于 2026-11-10 停止支持前安排运行时升级。
- [ ] 功能、数据格式或安装流程变化时同步更新 `docs/ai/` 和 `CHANGELOG.md`。
- [ ] 将编译、打包和所有者验收状态分别记录，避免混为一谈。
