# 数据模型、存储与迁移

> 维护提示：未来修改功能时候，更新此处详细信息。

- 最后核对日期：2026-09-14
- 当前 schema：设置 1；三个业务 JSON envelope 均为 version 1。

## 1. 日程模型

`CalendarItem` 是当前月历和详细日程的统一持久化记录：

| 字段 | 类型 | 规则/用途 |
| --- | --- | --- |
| `Id` | `Guid` | 非空；单条 occurrence 的身份。 |
| `Kind` | `CalendarItemKind` | `Class` / `Key` / `Idea` / `Inspiration`。 |
| `Title` | `string` | 必填；灵感最多 1000 字符，其余最多 240。 |
| `StartsAt` | `DateTimeOffset` | Class/Key 的准确起点；Idea/灵感也以此保存创建/归属时刻。 |
| `EndsAt` | `DateTimeOffset?` | Idea/灵感必须为空；Class 可空；Key 经 Service 规范后应有同日结束点。 |
| `IsCompleted` | `bool` | Class、Key、Idea 使用；Inspiration 在模型校验时规范为 `false`。完成的 Class/Key 不参与提醒，且在 UI 中置底灰化。 |
| `ColorKey` | `string` | 最多 32 字符，通常为 `palette-1..6`；是逻辑槽位，不是固定颜色。 |
| `CreatedAt` | `DateTimeOffset` | 稳定排序和创建信息。 |
| `Summary` | `string` | 仅 Key 使用，最多 3 个 Unicode 文本元素；详情色块展示完整 Title，月历按选择状态显示概述/名称。 |
| `TaskBatch` | `KeyTaskBatchInfo?` | 仅 Key 可有；非空即表示 Task 批次 occurrence。 |
| `FileLinks` | `IReadOnlyList<CalendarFileLink>` | 仅 Class/Key/Idea 使用，最多 32 条；保存文件或文件夹的完整路径、显示名、`IsDirectory`、置顶与添加时间，不保存内容。旧 JSON 缺失时按空集合读取。 |

`CalendarFileLink` 的 `FilePath` 必须是完整路径，同一路径不允许重复；`IsDirectory` 区分文件夹链接，一条日程最多一个链接为 `IsPinned=true`。存在性不属于领域校验：原文件/文件夹移动或被缓存清理后仍保留记录，供 UI 显示失效状态并按原类型“重新定位”。移除链接只删除地址，不得删除原内容。可执行文件、脚本和快捷方式在打开前由桌面端再次确认。

### Kind 语义与时间边界

- **Class**：可跨日期，允许单日；允许 `EndsAt == null`，表示当日仍未结束/长期项目。编辑器和拖拽都必须保证非空结束点不早于起点；标记完成后不再显示倒计时或触发提醒。
- **Key**：不得跨越开始日 24:00。若未输入结束点，`CalendarService.NormalizeDraft` 写入开始后 2 小时；超过午夜则写入次日 00:00，作为前一日 24:00。普通 Key 可在通用编辑器中标记完成。
- 普通 Key 和 Task Key 的编辑器在确认时若概述为空，按 Unicode 文本元素自动截取名称前三个字；不能直接按 UTF-16 `Substring(0,3)`，以免截断 emoji 或组合字符。
- **Idea**：当日便签，不具备结束时间，可勾选完成。
- **Inspiration**：UI 不要求选择日期；保存时仍有 `StartsAt` 与 `CreatedAt`，详情侧栏显示内容和创建时间。

Class/Key 完成状态的视觉和排序属于 UI 规则，但“不再产生提醒”由 `ReminderPlanner` 在进入 Kind 分支前统一过滤，不能只靠隐藏提醒窗口实现。

所有分钟编辑都应保留用户输入的分钟；只有月历外层边界拖动按现有交互吸附半小时。不要在 Domain 或仓储层统一舍入到半小时。

## 2. Task 批次

`Task` 通过 `KeyTaskSchedule` 创建多条 Key，并在每条上写入相同 `KeyTaskBatchInfo`：

| 字段 | 规则 |
| --- | --- |
| `BatchId` | 同批次共享；整批编辑和批次查询的键。 |
| `StartDate` / `EndDate` | 包含两端；结束不得早于开始；跨度最多 7305 天（约 20 年）。 |
| `WeekdaysMask` | 7 位星期位图，至少选择一天。 |
| `StartMinute` | `0..1439`。 |
| `EndMinute` | `1..1440` 且必须大于开始分钟。 |

`KeyTaskSchedule.Expand()` 最多生成 10000 条 occurrence。整批替换会保留原批次 ID、颜色槽和最早创建时间，但为新 occurrences 生成新 Item ID；同一日期仍存在时，保留该日期 occurrence 已绑定的快捷链接，且不会复制到其他日期。

交互语义必须保持：

- 双击 Task occurrence -> 用 `BatchId` 加载并编辑整个批次。
- 月历/详情拖动单次边界 -> 保存这一条 occurrence，不重算整批。
- 甩飞某 occurrence -> 只删除这一条。
- 整批编辑的 undo/redo -> 依赖 `KeyTaskBatchChange` 的 before/after 快照。

## 3. 日记模型

`DiaryEntry` 以 `DateOnly Date` 为唯一键，同一天最多一篇：

- `Title` 必填、最多 120 字符。
- `BodyPackageBase64` 保存 WPF `FlowDocument` package 的 Base64 字符串；插入图片会随文档包进入 JSON，文件可能快速增大。
- `PreviewText` 最多 240 字符，供纸张卡片预览。
- `SearchText` 是用于全文过滤的派生文本。
- `CreatedAt` 首次保存确定，后续覆盖保留；`UpdatedAt` 每次保存更新。

日记正文不是 Markdown/HTML。若未来换格式，必须提供 version 迁移，并保留旧文档包解析或转换路径。

`DiaryService.DeleteAsync(DateOnly)` 与仓储删除以日期为唯一键移除整篇记录，并沿用临时文件 flush、原子替换的写入流程。删除意味着标题、正文 package 及其中内嵌图片数据一起移除；UI 必须二次确认，且当前不提供撤销。

## 4. 工作模式模型

### `WorkGoal`

- 名称必填，最多 4 个 Unicode 文本元素。
- `ColorKey` 使用 `work-slot-1..6`。
- `IsBuiltIn` 标记默认“备考 / 冥想 / 休息”，默认项也允许重命名。
- `IsArchived` 用于隐藏不再使用但仍被历史 Session 引用的目标。

### `WorkSession`

- `GoalId` 引用工作目标。
- 活动录制为 `EndsAt == null`；服务保证同一时间最多一条活动录制。
- 开始时间向下取整到分钟。
- 正常结束必须晚于开始；单次最大 24 小时。读取/变更时服务会自动封顶过期活动录制。
- 允许跨午夜，因此按某天绘制/统计时必须用区间相交裁剪，不可仅比较开始日期。

### `WorkInterruption`

- 必须属于某个 Session。
- 活动中断可为 `EndsAt == null`；结束录制时一并关闭。
- 手动中断必须位于已结束 Session 内，不能与同 Session 的其他中断重叠。

目前服务和 ViewModel 仍有 `DeleteSessionAsync`，但产品要求关闭录制色块删除功能，现行 UI 不应调用它。

## 5. 设置模型

`AppSettings` schema 1 字段分组：

| 分组 | 字段 |
| --- | --- |
| 目录 | `CacheDirectory`、`LogDirectory` |
| 悬浮与启动 | `AutoFloatAndSleepWhenInactive`、`PinFloatingWindow`、`StartWithWindows`、悬浮窗 Left/Top |
| 快捷键 | `ExpandHotKey`，默认 `F8`；支持一个普通键或一个修饰键 + 普通键。 |
| 通知 | 总开关及 Class/Key/Idea 子开关。 |
| 色板 | Class、Key、Work 各 6 个十六进制颜色。 |

默认 Class 为较浅糖果色，Key 为较深糖果色，Work 为独立柔和色组。`CalendarPalette.ResolveColor` 根据事项 Kind 和同一 `palette-n` 分别选择 Class/Key 当前设置颜色，因此修改设置会立即影响既有事项。

## 6. 文件位置

### 固定应用根

| 构建 | 根目录 |
| --- | --- |
| Debug | `%LOCALAPPDATA%\DiaryOfMine.Dev` |
| Release | `%LOCALAPPDATA%\DiaryOfMine` |

固定 `userdata` 下：

- `appsettings.json`
- `reminder-acknowledgements.json`
- 默认 `cache\`
- 默认 `logs\`
- `vault\calendar.dat`（旧迁移源）
- `vault\diary.db`、`backups\` 目前只是预留路径，不代表 SQLite/备份已投入使用。

### 可切换缓存目录

| 文件 | 内容 | 加密状态 |
| --- | --- | --- |
| `DiaryOfMine.userdata.json` | `UserDataEnvelope(version, calendarItems)` | 明文 JSON |
| `DiaryOfMine.diary.json` | `DiaryEnvelope(version, entries)` | 明文 JSON |
| `DiaryOfMine.work.json` | `Envelope(version, state)` | 明文 JSON |

设置缓存目录变化时，`App.OnSettingsChanged` 对三个仓储调用 `SwitchDirectoryAsync`：

1. 新目录若已有目标文件，先验证并采用目标数据。
2. 新目录无目标文件时，把当前内存/文件状态复制写入新目录。
3. 任一步失败则回退路径并保留原文件；UI 显示错误。
4. 成功后刷新月历、详情、日记和工作模式，并重排提醒。

这不是跨目录自动合并。已有目标文件优先，修改流程不可无提示覆盖两边数据。

## 7. 写入可靠性和并发

三个 JSON 仓储共享以下约定：

- 用实例级 `SemaphoreSlim(1,1)` 串行读写。
- 在目标同目录创建 GUID `.tmp` 文件。
- 使用异步写、`WriteThrough`、`FlushAsync` 和 `Flush(true)`。
- 原文件存在时 `File.Replace`，否则 `File.Move`。
- finally 中尽力删除临时文件；解析失败时保留原文件并抛出 `InvalidDataException`。

领域记录、工作状态及设置使用 `JsonExtensionData` 保留当前版本不认识的属性；设置页保存从已加载快照更新，不能重新构造对象而丢弃未展示字段。缺失或为 `null` 的业务集合在读取时规范为空集合。顶层 envelope 保持最小固定结构；破坏性变化必须提升版本并提供显式迁移。完整规范见 [个人 JSON 兼容与升级规范](06-个人JSON兼容与升级规范.md)。

因此新增仓储或数据格式时应复用这个提交模式。不要先删除原文件，也不要在解析失败时自动写空集合。

## 8. 旧数据迁移

仅日程有旧迁移：当现行 `DiaryOfMine.userdata.json` 不存在且旧 `userdata\vault\calendar.dat` 存在时，`PortableJsonUserDataRepository` 用 `EncryptedJsonCalendarRepository` 和 Windows DPAPI CurrentUser 解密，读出全部事项后写入新 JSON。迁移尝试在本仓储实例中只做一次。

注意：迁移结果是明文 JSON。若未来恢复加密，必须作为新 schema/新仓储明确实现，不能只修改 README 描述。

## 9. 清理与隐私边界

- 设置页“清空日程”只清空 `DiaryOfMine.userdata.json`，随后重置月历和已打开详情的状态；不删除日记、工作记录、设置和日志。
- 卸载器当前默认保留 `%LOCALAPPDATA%` 用户数据。
- 发布脚本只能收集 `dotnet publish` 输出、安装/卸载宿主和发布说明；禁止复制 `userdata`、自定义缓存目录、日志、截图或任何测试输入。
- 日记包中可能含图片原始数据，隐私扫描不能只搜索文本内容，也要检查文件名和目录来源。
