# 个人 JSON 兼容与升级规范

> 维护提示：未来修改功能时候，更新此处详细信息。

- 最后核对日期：2026-09-13
- 适用范围：设置、日程、日记、工作模式四类长期个人数据。
- 当前版本：`appsettings.json` schema 1；三个业务 JSON envelope version 1。

## 1. 兼容目标

软件更新不得因为新增字段、旧文件缺少集合、读取失败或设置页未展示某个字段而静默丢失用户数据。当前实现采用两层保护：

1. **同版本的增量拓展**：领域记录、工作状态和设置通过 `JsonExtensionData` 暂存当前程序不认识的属性；记录被编辑并再次保存时，这些属性仍会写回。
2. **不兼容版本保护**：读取端只接受自己明确支持的版本。遇到更高版本或格式错误时抛出错误并保留原文件，禁止自动回退为空数据后覆盖。

`version/schemaVersion` 只表示持久化结构，不与产品版本号绑定。

## 2. 当前文件与版本边界

| 文件 | 顶层结构 | 兼容策略 |
| --- | --- | --- |
| `appsettings.json` | `AppSettings`，含 `SchemaVersion` | 设置模型保留未知属性；保存从已加载快照做 `with` 更新。 |
| `DiaryOfMine.userdata.json` | `{ version, calendarItems }` | `CalendarItem`、文件链接和 Task 批次信息保留未知属性。 |
| `DiaryOfMine.diary.json` | `{ version, entries }` | `DiaryEntry` 保留未知属性。 |
| `DiaryOfMine.work.json` | `{ version, state }` | `WorkModeState`、目标、记录和中断分别保留未知属性。 |

业务 envelope 顶层仅允许版本号和固定 payload 字段；未来可扩展元数据应优先放入 payload 状态或记录中。若必须改变 envelope，必须升级版本并迁移，不能依赖顶层未知字段回写。

提醒确认文件是可重新生成的辅助状态，不属于不可替代的核心个人内容，但仍须在版本不支持时拒绝覆盖。

## 3. 新增字段的规则

同一 schema/version 内只允许兼容式新增：

- 新属性必须可选，或具有不会改变旧数据含义的默认值。
- 集合不得把 `null` 当作业务状态；读取旧文件时统一规范为空集合。
- 不得复用、改名或改变现有 JSON 属性的含义和类型。
- 不得用界面显示文字充当永久业务键；颜色继续保存稳定槽位，关联继续保存 `Guid`。
- `DateOnly` 保持 ISO 日期语义；精确时刻保存 `DateTimeOffset` 及偏移；日程时间保持分钟精度。
- 枚举新增值前需确认旧版本处理策略。旧版本不能理解的新语义通常应触发版本升级。

编辑服务使用 `with` 或从旧对象复制时，必须保留 `ExtensionData`。批量重建（尤其 Task occurrence）还要明确保留同一逻辑记录的 ID、创建时间、文件链接及未知数据。

## 4. 何时必须升级版本

以下变化不能留在 version 1：属性改名或删除、属性类型变化、时间/ID 语义变化、拆分或合并记录、正文编码格式变化、envelope 结构变化、旧程序读后会错误改写的新状态。

升级流程必须是：

1. 先完整反序列化旧版本到旧结构。
2. 按 `N -> N+1` 独立迁移，逐级执行，不跨级猜测。
3. 在内存中验证数量、ID、引用和时间边界。
4. 迁移成功后才使用同目录临时文件原子替换；失败时原文件保持不动。
5. 记录迁移结果，但日志不得写入日记正文、标题或完整私人路径。

旧版程序遇到未来版本时应明确拒绝加载/保存，不能用默认值覆盖未来数据。

## 5. 写入与目录切换

- 所有长期 JSON 写入都应串行化。
- 临时文件必须位于目标文件同目录，写入后 flush，再用 `File.Replace` 或首次 `File.Move` 提交。
- finally 尽力删除临时文件；绝不先删正式文件。
- 解析失败不得自动创建空文件。
- 切换缓存目录时先验证目标；目标已有数据则采用目标，目标为空才复制当前数据；失败回滚目录设置。
- Demo、安装包和完整软件输出不得携带这些 JSON、日志或测试数据。

## 6. 每次数据模型修改的最低检查清单

1. 旧 version 1 样本缺少新增字段时仍能读取。
2. 在 JSON 中注入一个未知属性，读取、编辑已知字段、保存后未知属性仍存在。
3. 集合字段缺失或为 `null` 时被规范为空集合，且不会清空其他记录。
4. 更高版本和损坏 JSON 均拒绝加载，原文件字节不被覆盖。
5. Task 批量替换、日记覆盖、工作目标改名及设置保存不会丢失未参与编辑的字段。
6. 同目录原子写入路径可完成；失败只遗留可清理的 `.tmp`，正式文件仍可读取。

数据模型发生变化时，应同步更新本规范、`02-数据模型-存储与迁移.md`、根 README 更新日志及相关模块索引。
