## 1. 软件定位

Diary of Mine 是单机、单用户、Windows 本地优先的日程/日记/工作计时应用。它当前有三个同级主页面：

| 导航 ID | 页面 | 核心用途 |
| --- | --- | --- |
| `home` | 日程表 | 月历、Class、Key、Idea、Task 批量排布、单日详情 |
| `diary` | 日记 | 按日期浏览、检索、图文编辑 |
| `work` | 工作模式 | 对工作目标计时、记录中断、查看统计 |
| `settings` | 设置（底部） | 本地目录、通知、悬浮行为、热键、自启、色板、清空日程 |

应用不包含 Web 服务；`App.xaml.cs` 是组合根，直接创建仓储、服务、ViewModel 和窗口协调器。运行时只有一个应用实例，子窗口由主进程管理。

## 2. 架构事实

```text
DiaryOfMine.Desktop
  ├──> DiaryOfMine.Application ──> DiaryOfMine.Domain
  └──> DiaryOfMine.Infrastructure ──> DiaryOfMine.Application
```

- `Domain`：模型本身验证不变量。
- `Application`：执行业务用例，规范时间、批次、目标和提醒；只依赖抽象仓储。
- `Infrastructure`：JSON 文件、设置、日志、旧 DPAPI 日程迁移。
- `Desktop`：WPF UI、画布渲染、拖拽/悬停、子窗口和 Windows 集成。

本项目不是纯粹的 XAML/MVVM：月历、详细日程和工作模式包含大量即时绘制及鼠标状态机，因此主要在 `.xaml.cs` 中。正确改法通常是：界面捕获手势 -> ViewModel 表达页面动作和独立历史 -> Application Service 校验/变更 -> Repository 原子写入 -> 事件触发其他视图刷新。

## 3. 最重要的业务术语

| 名称 | 实际含义 |
| --- | --- |
| Class | 有开始时间、可跨天的事项；允许只持续一天，也允许无结束时间；可标记完成。 |
| Key | 只能在开始当天结束的精确时间事项；未填结束时间时真实写入“开始后 2 小时”，但最多到当日 24:00；普通 Key 可标记完成。 |
| Idea | 无结束时间的当日便签，可勾选完成。 |
| Inspiration | 无日期选择界面的灵感内容；仍使用创建时刻归入存储和显示创建时间。 |
| Task | 不是第五种 `CalendarItemKind`。它是具有相同 `TaskBatch.BatchId` 和排布规则的多条 Key occurrence。 |
| 工作目标 | 最多 4 个文本元素的计时分类；内置目标首次使用时创建，也可重命名。 |
| 工作录制 | 一个目标对应的开始/结束区间；同一时刻仅允许一个活动录制，单次最长 24 小时。 |

## 5. 当前易错事实

1. 当前三个主要业务文件是**明文 JSON**；只有旧 `calendar.dat` 是 DPAPI 数据源。不要在 UI、README 或发布说明里把当前缓存误称为已加密。
2. 设置页“清空日程”调用 `CalendarService.ClearAsync`，只清除日程 JSON，不清除日记和工作模式。
3. 主月历和单日详情各自拥有独立的内存撤销/重做栈；切换单日详情日期不清空其工作区历史，但关闭/新建窗口后的历史不持久化。
4. 双击 Task occurrence 打开的是整个批次编辑；甩飞删除、边界拖动某一 occurrence 只针对当天那条 Key。
5. 工作录制色块的 UI 删除入口已经关闭，但 Application/ViewModel 中仍保留 `DeleteSessionAsync`；除非需求明确，不要重新暴露删除手势。
6. 设置色板保存的是 `palette-*` / `work-slot-*` 逻辑槽位对应颜色。现有事项应实时解析槽位，因此设置变化会作用于旧数据。
7. `LinksPageView` / `LinksPageViewModel` 是历史命名，当前实际承载“日记”页，不是链接功能。
8. 2026-09-12 安装器修复只在源码中；不得宣称现存安装包已经修复。
9. Class/Key/Idea 共用 `IsCompleted`；完成的 Class/Key 在两套日程 UI 中置底、灰化、名称加删除线，并由提醒规划器统一过滤。月历和详情均可用 `Shift + 左键` 快捷切换；Task occurrence 只修改被点击的单条 Key，批次编辑器目前不提供整批完成选项。
10. 长期 JSON 记录和设置保留未知属性；同版本只做兼容式新增，破坏性结构变化必须升级版本并显式迁移。旧程序遇到不支持的更高版本时必须拒绝覆盖原文件。
11. 日记删除以 `DateOnly` 为键删除整篇并原子重写日记文件；月历圆圈来自日记仓储中的真实日期集合，保存、删除和缓存目录切换后必须同步刷新。
